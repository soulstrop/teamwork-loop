# Inbox

**The job:** hold an idea that has no home yet, visibly, so that *unrouted* is a
state somebody can see rather than a file that appeared in `docs/`.

**Not the job:** being a home. Nothing lives here. An entry is either routed or
deleted, and both are normal outcomes.

## Why it exists

A document set with a routing question still receives things the question does
not answer: a half-formed idea, a note from a conversation, an approach worth
remembering but not worth deciding on, a performance investigation nobody asked
for. Without a named place, these land wherever is nearest — usually the
document that will accept anything, which in this set is the handoff, and the
handoff is deleted on purpose.

So the inbox trades one failure for a smaller one. Material with no home is
visible and dated instead of scattered or lost, at the cost of a directory that
has to be swept.

## The rules

**Everything here is dated and gets a one-line statement of what it is.** A file
whose subject cannot be stated in a line is a file nobody will open again.

**Sweep it at a release boundary**, and ask of each entry: has this become
routable? Almost all of them resolve to a design note, an ADR, a roadmap open
item, a stakeholder question, or the bin.

**An entry that survives three sweeps is telling you something.** Either it is a
category the routing question is missing — which is a process finding, not a
filing problem — or it is not actually interesting and the honest act is deleting
it. Both outcomes are worth more than a fourth sweep.

**References go next door.** External material — a paper, a specification, a
vendor document — belongs in [`../references/`](../references/README.md), which
is a different thing: those are permanent and cited, not pending.
