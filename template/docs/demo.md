## Setting up

*The commands, in order. Two properties worth having:*

*Build the demonstration through the application's **own** interface rather than
by writing state directly. A direct write proves nothing about the paths a person
uses and can create state the application would have refused — so a failed setup
run becomes a finding about the release rather than a broken script.*

*Make it disposable and repeatable. A demonstration environment that has to be
nursed is one that will be broken on the morning it matters.*
